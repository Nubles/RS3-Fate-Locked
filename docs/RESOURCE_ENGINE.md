# The Resource Engine

The Resource Engine is the modal at `components/SupplyChainCalculator.tsx`. It
lets a player search for a RuneScape 3 item and see every way to acquire it,
with each source individually marked as **available** or **locked** against
the current game state. ~700 curated items, ~800 sources, recursive material
breakdown, favourites, category browser.

This document is the maintainer's map of how the data, the analyzer, the
generators, and the integrity tests fit together.

---

## 1. Data shape

### `ResourceSource` (`data/resourceData.ts`)

```ts
interface ResourceSource {
  type:    'DROP' | 'SHOP' | 'SPAWN' | 'SKILL' | 'MINIGAME' | 'MERCHANT' | 'QUEST'
         | 'PICKPOCKET' | 'CLUE';
  name:    string;                 // monster / shop / activity name
  regions: string[];               // 'Any', continent, continent child, Misthalin area
  skills?: Record<string, number>; // RS3 skill names, e.g. { 'Slayer': 85, 'Constitution': … }
  quests?: string[];               // official RS3 quest titles (QUEST_DATA)
  unlockId?: string;               // must be in BOSSES_LIST / MINIGAMES_LIST / FARMING_PATCH_LIST / …
  inputs?:  Record<string, number>;// recipe: { 'Rune Bar': 5 }
  outputYield?: number;            // items produced per operation
  notes?:   string;
  rarity?:  string;                // drop rate, e.g. '1/512' / 'Always'
}
```

### `RESOURCE_MAP` and `RESOURCE_CATEGORIES`

`Record<string, ResourceSource[]>` keyed by item display name (Title Case,
e.g. `"Black D'hide Body"`, `"Clean Ranarr"`). **The keys are the canonical
item names** — every input, every category, every test references them.

`data/resourceData.ts` declares items per browsing category with a
`section(category, items)` helper that fills **both** `RESOURCE_MAP` and
`RESOURCE_CATEGORIES`, so an item can't exist without a category. Regular
families are generated by small helpers from verified RS3 tables:

| Helper | Family | RS3 facts encoded |
|---|---|---|
| `HERBS` | 19 clean herbs incl. spirit weed, wergali, bloodweed, arbuck, fellstalk | herb-patch Farming levels; `unlockId: 'Herb'` |
| `brew` / `upgrade` | 39 potions, attack potion → elder overload | RS3 Herblore levels/ingredients (extremes, overload 96, supreme 98, elder 106) |
| `smithTier` | Bronze → Rune (25 items each) and Orikalkum / Necronium / Bane / Elder rune | post-2018 rework: every base item at the metal's level; 1/2/3/4/5-bar costs |
| `smelt` | bars incl. orikalkum, necronium, bane, elder rune | adamant/rune need luminite; elder rune = rune bar + light + dark animica |
| `FISH` | 25 raw + cooked fish (rocktail, sailfish, great white shark, blue blubber jellyfish, …) | Fishing and Cooking levels, Deep Sea Fishing / Trawler / LRC / Menaphos |
| `craftRune` | elemental, catalytic, time, mud and Necromancy runes | RS3 altar levels; Runespan source; impure essence for necromancy runes |
| `JEWELS` | gold → onyx jewellery + enchanted names | Crafting levels, enchant level + runes |
| `WISPS` / `MATERIALS` | Divination energies, Archaeology materials | wisp level + colony, material-cache level + dig site |

### `ENRICHED_SOURCES` (auto-generated)

`data/resourceEnrichment.ts` is **generated** (see §3) and *imported* by
`resourceData.ts`. After all sections are declared:

```ts
for (const [item, extra] of Object.entries(ENRICHED_SOURCES)) {
  const target = RESOURCE_MAP[item];
  if (target) target.push(...extra);
}
```

So the in-memory `RESOURCE_MAP` is curated entries + wiki-enriched entries,
merged at load. Do **not** hand-edit `resourceEnrichment.ts` — re-run the
generator. **It is currently empty**: the previous contents came from the
Old School wiki and were dropped in the RS3 conversion; regenerating it needs
network access (see §3).

`ITEM_CATEGORY` is the reverse lookup (item → category) used by the UI.

## 2. The analyzer (`utils/supplyChain.ts`)

```ts
buildAvailabilityContext(gameState): AvailabilityContext
analyzeSource(source, ctx, collectMissing): RouteStatus
isSourceAvailable(source, ctx): boolean
calculateSupplyChain(itemName, gameState): SupplyChainResult
isItemAvailable(itemName, gameState): boolean
isItemAvailableWithCtx(itemName, ctx): boolean
computeFullBreakdown(itemName, qty, path?): MaterialNode
flattenRawMaterials(node): { item, qty }[]
```

Key shape: `analyzeSource` is the single source of truth for "is this source
unlocked?". It powers both the detail UI (`collectMissing: true` populates
`missing: string[]`) and the boolean hot path (`collectMissing: false` short-
circuits).

`AvailabilityContext` turns the player's `gameState.unlocks.*` arrays into
`Set`s once; the inner check then uses O(1) lookups instead of repeatedly
scanning arrays. **When iterating many items, use
`isItemAvailableWithCtx` and build the context once** — the Resource Engine's
availability map does this for ~700 items per game-state change.

`computeFullBreakdown` walks the first recipe-style source (one with `inputs`)
for each item, scaling by `outputYield`, with depth (10) + cycle guards.

## 3. Generator / audit scripts

Three authoring tools live in `scripts/`. They read the RS3 wiki
(`runescape.wiki`) bucket API with `curl`, and need network access (they
can't run in the sandboxed CI). None is imported at runtime.

### `scripts/buildCraftables.mjs`

- **Pulls:** Smithing, Crafting and Magic (enchant) recipes from the `recipe`
  bucket.
- **Scope:** the six standard metals and the four elite metals (base items
  only — no +1…+5 upgrades, off-hands, ore boxes, mattocks), leather and
  d'hide armour, gems, gold → onyx jewellery and its enchantments.
- **Reports** curated recipes whose level or inputs disagree with the wiki
  (fix them in the `resourceData.ts` helper tables), and writes paste-ready
  `section(...)` blocks for in-scope wiki items the catalogue lacks to
  `scripts/_craftables.generated.txt`. It never edits data files.

### `scripts/buildPotions.mjs`

- **Pulls:** Herblore recipes; flattens `(unf)` steps into herb + vial of
  water; collapses one-row-per-dose duplicates; maps wiki names (`Super
  ranging (3)`) to app keys (`Super Ranging Potion`).
- **Excludes:** juju potions, Barbarian mixes, flasks/salves/bombs, Herblore
  Habitat god potions, aggroverloads/holy/searing variants.
- **Reports** Herblore-level mismatches and writes new entries to
  `scripts/_potions.generated.txt`.

### `scripts/buildSourceEnrichment.ts`

- **Pulls:** `storeline` (shops), `dropsline` (drops), `infobox_monster`
  (monster name + League region), `infobox_shop` (shop name + location).
- **For each `RESOURCE_MAP` item**: adds up to 3 SHOP sources and up to 6
  DROP sources from the wiki.
- **Curation applied:**
  - Strips wiki page anchors / sub-paths (`Lundail#Easy Diary` → `Lundail`).
  - Skips skilling "drop tables" (rocks, trees, patches) — already covered as
    SKILL sources.
  - Names drop sources from clue caskets as `CLUE` type, others `DROP`.
  - Resolves `unlockId` by matching the drop-source name against
    `BOSSES_LIST` ∪ `MINIGAMES_LIST`, an RS3 alias table (full boss titles such
    as `Telos, the Warden`, encounter members such as `Dagannoth Rex` or
    `Legio Primus`, elite-dungeon end bosses) and reward-chest parentheticals.
    When set, realigns the region to `ACTIVITY_REGIONS[unlockId]`.
  - Drop region: drop_json's League region → infobox_monster's
    `league_region` → `'Any'`. RS3 League regions without a single app
    continent (Havenhythe, Equilibrium, …) fall through to `'Any'`.
  - Shop region: a small hand-curated `SHOP_REGION` map → infobox_shop's
    `[[Place]]` location mapped via `REGION_GROUPS` / `MISTHALIN_AREAS` → `'Any'`.
- **Self-reference guard:** strips its own previous output off `RESOURCE_MAP`
  before deduping.
- **Writes:** `data/resourceEnrichment.ts`, overwriting the whole file.
- **Re-run after:** adding curated items or changing the unlock lists.

The bucket names and fields above are the Weird Gloop schema; they could not
be verified against runescape.wiki from the conversion sandbox. Each script
throws on a non-bucket response instead of writing partial output.

## 4. Wiki Bucket API conventions

Endpoint: `https://runescape.wiki/api.php?action=bucket&format=json&query=…`

- The `query` is a tiny Lua expression: `bucket('table_name').select('a','b').limit(5000).run()`
- Bucket names are **lowercase / snake_case** (`dropsline`, `infobox_monster`).
- Hard cap of **5000 rows per query** — paginate with `.offset(N)`.
- The wiki's anti-bot layer blocks Node `fetch`; the scripts shell out to
  `curl` with a desktop User-Agent.

## 5. Integrity tests

`data/resourceConsistency.test.ts` is the contract:

1. **Categories cover RESOURCE_MAP exactly** — every item in exactly one
   category (guaranteed by `section()`, still tested).
2. **Source well-formedness** — every source has at least one region.
3. **Unlock-gated sources sit in the activity's region** — a source with an
   `unlockId` that `ACTIVITY_REGIONS` knows must list that continent, one of
   its sub-areas (e.g. `God Wars Dungeon` for Fremennik, `Wizards' Tower` for
   Misthalin), or `'Any'`.
4. **`computeFullBreakdown` always terminates**.
5. **Inputs resolve** — every recipe input is a `RESOURCE_MAP` key, `'Coins'`,
   or on `INTENTIONAL_INPUT_LEAVES` (empty after the RS3 rewrite — prefer
   adding the item).
6. **Unlock IDs resolve** — every `unlockId` is in one of the unlock lists.
7. **Skill names resolve** — every `skills` key is in the RS3 `SKILLS_LIST`.
8. **Region tags resolve** — `'Any'`, a continent, a continent child, or a
   Misthalin area. Old School regions (Kourend & Kebos, Varlamore, The Open
   Seas, Fossil Island, …) fail this test.

`data/resourceChunkTruth.test.ts` cross-checks DROP sources against
`public/chunk-content.json` (see §7).

## 6. Adding a curated item — the workflow

1. **Add it to a `section()`** in `data/resourceData.ts` (or to a helper
   table such as `HERBS`, `FISH`, `STANDARD_ITEMS`). Use the canonical Title
   Case name. Every source needs at least `type`, `name`, `regions`.
2. **Use RS3 facts** — verify levels and recipes on runescape.wiki.
3. **Make sure inputs link** — every `inputs` key should be a `RESOURCE_MAP`
   item. Tools used but not consumed go in with quantity `0`
   (`'Hammer': 0`).
4. **Tag the most specific area** (`'God Wars Dungeon'`, `'City of Um'`) when
   a source lives in one place, so that sub-area's unlock gates it.
5. **Run the suite:** `npx tsc --noEmit && npx vitest run`.

## 7. Region & unlock conventions

- **`REGION_GROUPS`** (`data/items.ts`) is the RS3 continent → sub-area map
  (Asgarnia, Kandarin, Karamja, Kharidian Desert, Morytania, Fremennik,
  Tirannwn, Wilderness, Daemonheim, Anachronia, The Arc, Islands & Others);
  Misthalin's sub-areas live in `MISTHALIN_AREAS`. Both are valid `regions`
  tags, as is `'Misthalin'` itself.
- **`ACTIVITY_REGIONS`** (`data/activityRegions.ts`) is the source of truth
  for which continent a boss/minigame lives in (Telos → Wilderness, Vorago →
  Asgarnia, Rasial → Morytania, Deep Sea Fishing → Kandarin, …).
- Farming sources carry the patch type as `unlockId` (`'Herb'`, `'Bush'`,
  `'Tree'`, `'Cactus'`, …) from `FARMING_PATCH_LIST`.
- **Chunk data.** `public/chunk-content.json` is built from RS3 cache data
  (mejrs `data_rs3`: NPC spawns, objects, map labels) by
  `scripts/sync-chunk-content.mjs`, on the RS3 map grid (`cx = x>>6`,
  `cy = y>>6`). `utils/chunkResources.ts` gates gathering nodes with RS3
  levels, including RS3-only nodes such as necrite, banite and elder trees.

## 8. Image lookups (`services/WikiService.ts`)

- Item names in the app are title case but wiki articles are sentence case
  (`Clean Ranarr` vs `Clean ranarr`). The service queries **both**
  the title-cased title and a sentence-cased variant in the same batch, and
  falls back to the variant when the title-cased page has no image. This
  fixes images app-wide without breaking proper-noun pages (bosses).
- `WIKI_OVERRIDES` (`data/assets.ts`) is the escape hatch for names that
  hit a disambiguation page (e.g. `Gnome Village` →
  `Tree_Gnome_Village`). Store the **raw** wiki page name — do not
  URL-encode; `URLSearchParams` does that for you.
- `CACHE_KEY = 'fate_uim_wiki_cache_v3'`. Bump the version suffix whenever
  the resolution logic changes so stale null cache entries are dropped.

## 9. Known limitations / deferred work

- **Enrichment is empty** until `buildSourceEnrichment.ts` is re-run against
  the RS3 wiki with network access; until then shops/drops are the curated
  ones only.
- **Not modelled yet:** Invention components and gizmos, Necromancy rituals
  and inks, Summoning pouches, Dungeoneering, Hunter/Farming produce beyond
  the potion secondaries, hydrix jewellery, elite-tier weapon lines beyond
  those listed, +1…+5 smithing upgrades, juju/combination potions.
- **Chunk data gaps.** The cache data has no quest steps, shop stock or
  Slayer master tables, lodestone positions are hand-written, and the Arc
  and Havenhythe are off the map grid.
- **GE prices** integration was deliberately deferred. `services/PriceService.ts`
  exists.

## 10. Common commands

```sh
# Type-check
npx tsc --noEmit

# Run the test suite (integrity guards are in here)
npx vitest run

# Audit curated recipes against the RS3 wiki (network required)
node scripts/buildCraftables.mjs
node scripts/buildPotions.mjs

# Refresh wiki-sourced shop/drop enrichment (network required)
npx tsx scripts/buildSourceEnrichment.ts
```
